# L0504: `variable` mark does not match the parameter

An argument is passed to a `variable` parameter without the `variable` mark, or is marked `variable` for a parameter that cannot change it. Only a `variable` binding can be passed with the mark.

## Example

```lymra
function increment(variable integer64 count)
    count = count + 1

function main()
    variable integer64 total = 0
    increment(total)
    print("{total}")
```

## Why

A call that can change one of your bindings has to say so where the call is written (spec section 5). Reading `increment(total)`, anyone would assume `total` stays the same. With `increment(variable total)`, the change is visible on the line where it happens. A mark on an argument the function cannot change would claim a change that never happens.

## Fix

Mark the argument exactly when the parameter is `variable`.

```lymra
function increment(variable integer64 count)
    count = count + 1

function main()
    variable integer64 total = 0
    increment(variable total)
    print("{total}")
```
