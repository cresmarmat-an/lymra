# L0404: number does not fit its type

A number is outside the range of its type, or arithmetic on values known at compile time always overflows.

| Type | Range |
|---|---|
| `integer8` | -128 to 127 |
| `integer16` | -32768 to 32767 |
| `integer32` | -2147483648 to 2147483647 |
| `integer64` | -9223372036854775808 to 9223372036854775807 |
| `unsigned8` | 0 to 255 |
| `unsigned16` | 0 to 65535 |
| `unsigned32` | 0 to 4294967295 |
| `unsigned64` | 0 to 18446744073709551615 |

## Example

```lymra
function main()
    constant unsigned8 level = 300
    print("{level}")
```

## Why

A value outside its type's range would have to wrap around or be cut, and either way the program would compute with a different number than the one written.

Literals are computed exactly before they get a type, so only the final value has to fit: `constant unsigned8 small = 300 - 100` is fine. When every value in an expression is known at compile time, the compiler computes it, and an overflow is reported here instead of when the program runs. Overflow that depends on values known only at run time stops the program with a runtime error.

## Fix

Use a value in range, or a wider type.

```lymra
function main()
    constant unsigned16 level = 300
    print("{level}")
```
