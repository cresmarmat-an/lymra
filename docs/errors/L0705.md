# L0705: handle used with another pool

A handle reads or changes a value only in the pool it came from: the pool whose `insert` gave it.

## Example

```lymra
type Creature
    integer32 health

function main()
    variable pool[Creature] wolves = pool()
    variable pool[Creature] sheep = pool()
    constant wolf = insert(variable wolves, Creature(health = 5))
    constant lamb = insert(variable sheep, Creature(health = 2))
    print("{sheep[wolf].health} {lamb == wolf}")
```

## Why

A handle is a slot number and the generation of that slot. `sheep` has a slot with the same number, quite likely in the same generation, so the check that catches a removed value would pass and `sheep[wolf]` would read a sheep as if it were the wolf: the right type, the wrong data, and no error to say so.

The compiler follows every handle from the `insert` that made it, through bindings, lists, the fields of other values and the calls in between, with no annotations. A function that takes a pool and a handle into it is checked at every call: each handle it gets has to come from the pool it gets with it.

## Fix

Use each handle with the pool it came from:

```lymra
type Creature
    integer32 health

function main()
    variable pool[Creature] wolves = pool()
    variable pool[Creature] sheep = pool()
    constant wolf = insert(variable wolves, Creature(health = 5))
    constant lamb = insert(variable sheep, Creature(health = 2))
    print("{wolves[wolf].health} {sheep[lamb].health}")
```
