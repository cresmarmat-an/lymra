# L0305: syntax from another language

The code uses a spelling from another language where Lymra has its own. The message names the Lymra spelling, and the compiler keeps checking the rest of the line as if you had written it.

| Instead of | Write |
|---|---|
| `fn`, `def`, `func` | `function` |
| `let`, `var`, `const` | `variable` or `constant` |
| `struct`, `class` | `type` |
| `i64`, `u8`, `f64`, `bool`, `str` | `integer64`, `unsigned8`, `float64`, `boolean`, `string` |
| `int`, `float` | a type that states its size, such as `integer64` or `float32` |
| `enum` | `choice` |
| `import` | `use` |
| `pub`, `export` | `public` |
| `elif`, `elsif` | `else if` |
| `&&`, <code>&#124;&#124;</code>, `!` | `and`, `or`, `not` |
| `===`, `!==` | `==`, `!=` |
| `-> T` after a function | `returns T` |
| `name: T` | `T name` |
| `x += 1`, `x++` | `x = x + 1` |
| `0..10` | `range(0, 10)` |
| `{` and `}` around a block | indentation |
| `:`, `then`, `do` at the end of a header | nothing |
| `;` at the end of a statement | nothing |
| `//` and `/* */` comments | `#` and `#[ ]#` |
| `'text'` | `"text"` |
| `use item from module` | `use module.item` |

## Example

```lymra
fn main() {
    let total = 0;
    if total == 0 && !done {
        total += 1;
    }
}
```

## Why

Lymra has one way to write each thing (spec goal 4), and every name the language defines is a whole English word. Accepting `fn` next to `function`, `i64` next to `integer64`, or `&&` next to `and`, would mean every reader has to know both.

These get their own error code because they are habits, not confusion. The fix is always a direct translation.

## Fix

Use the Lymra spelling from the table.

```lymra
function main()
    variable total = 0
    if total == 0 and not done
        total = total + 1
```
