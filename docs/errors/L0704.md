# L0704: value changed while a newer value sits above it

A list, a stack or a pool can only change, with `push`, `pop`, `insert` or a replacement, while it is the newest value on its data stack. A function that calls itself can be handed a list from an earlier call that its own lists sit above.

## Example

```lymra
function digits_of(variable list[integer64] digits, integer64 value)
    variable list[integer64] higher = list()
    if value >= 10
        digits_of(variable higher, value / 10)
    for digit in higher
        push(variable digits, digit)
    push(variable digits, value % 10)

function main()
    variable list[integer64] digits = list()
    digits_of(variable digits, 2026)
    print("{length(digits)}")
```

## Why

Lists live on data stacks. The newest list on a data stack sits on top, and only that one can grow: it grows into the free space above it, so its elements never move and nothing needs a capacity check. A stack shrinks the same way, by moving the top of its data stack down over its last element, so popping a stack with a newer one above it would free part of the newer one. Freeing a list is one store. Each list binding has a data stack of its own, so the lists of one call never get in each other's way.

The copies of one binding in a recursion share a data stack, each above the copy of the call before it. Here every call passes its `higher` down as `digits`, so inside a call, `digits` is the `higher` of the call before, and this call's own `higher` sits right on top of it. Growing `digits` would write over `higher`. C++ and Rust would move the list somewhere else on the heap; Lymra has no heap and never moves a list, so it rejects the program before it runs.

Text works the same way. A binding keeps its text on a data stack, and new text for it goes where the old text starts, so a function that calls itself can't give new text to a `variable` parameter whose text sits below text of its own call.

The compiler follows where each list and text can travel through calls, so the error only comes where one really can be under a newer one.

## Fix

Let every call add to the one list it was given:

```lymra
function digits_of(variable list[integer64] digits, integer64 value)
    if value >= 10
        digits_of(variable digits, value / 10)
    push(variable digits, value % 10)

function main()
    variable list[integer64] digits = list()
    digits_of(variable digits, 2026)
    print("{length(digits)}")
```

Or return a new list instead of filling the caller's:

```lymra
function digits_of(integer64 value) returns list[integer64]
    variable list[integer64] digits = list()
    if value >= 10
        digits = digits_of(value / 10)
    push(variable digits, value % 10)
    return digits

function main()
    print("{length(digits_of(2026))}")
```
