# L0114: invalid number

A number literal is not written in a form Lymra accepts.

| Form | Examples |
|---|---|
| decimal integer | `42`, `1_000_000` |
| hexadecimal | `0xFF` |
| binary | `0b1010` |
| float | `3.14`, `1.0e-9` |

## Example

```lymra
constant a = 007
constant b = 1e9
constant c = 42u8
constant d = 1__000
```

## Why

Each rejected form hides a trap or is a second spelling of something that already has one:

- A leading zero means octal in C, so `010` is 8 there. Lymra rejects it instead of picking a meaning.
- A float needs digits on both sides of the point. `1e9` is written `1.0e9`.
- The prefixes `0x` and `0b`, and the exponent marker `e`, are lowercase.
- An underscore goes between two digits, one at a time.
- A number has no type suffix. The type comes from the declaration.
- A number cannot run straight into letters, as in `12abc`.
- The value has to fit: at most 18446744073709551615 for an integer.

## Fix

Write the number in one of the accepted forms. The message shows the corrected spelling when there is exactly one.

```lymra
constant a = 7
constant b = 1.0e9
constant unsigned8 c = 42
constant d = 1_000
```
