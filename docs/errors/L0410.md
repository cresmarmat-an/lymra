# L0410: array too large for the call stack

An array lives on the call stack, and one array takes at most 1 MiB (1048576 bytes): its length times the size of one element. An `integer64` takes 8 bytes, so `array[integer64, 131072]` is the largest array of them.

## Example

```lymra
function main()
    variable array[integer64, 1000000] samples = array(0)
    samples[0] = 1
    print("{samples[0]}")
```

## Why

A thread's call stack is a few MiB in all, and every call in progress keeps its values there. An array larger than that could never run: the program would stop with a stack overflow the moment the function started. Rejecting it while compiling says what is wrong and where, instead of a crash with no location. The 1 MiB limit leaves room for several large arrays, a copy of one, and the calls between them.

## Fix

Use fewer or smaller elements. A `list`, which phase 3 adds, lives on a data stack instead, which holds gigabytes.

```lymra
function main()
    variable array[integer64, 100000] samples = array(0)
    samples[0] = 1
    print("{samples[0]}")
```
