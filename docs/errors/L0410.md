# L0410: value too large for the call stack

Arrays and values of declared types live on the call stack, and one such value takes at most 1 MiB (1048576 bytes). An array takes its length times the size of one element, so with 8 bytes for an `integer64`, `array[integer64, 131072]` is the largest array of them. A declared type takes the sizes of its fields together.

## Example

```lymra
function main()
    variable array[integer64, 1000000] samples = array(0)
    samples[0] = 1
    print("{samples[0]}")
```

## Why

A thread's call stack is a few MiB in all, and every call in progress keeps its values there. An array larger than that could never run: the program would stop with a stack overflow the moment the function started. Rejecting it while compiling says what is wrong and where, instead of a crash with no location. The 1 MiB limit leaves room for several large arrays, a copy of one, and the calls between them.

## Fix

Use fewer or smaller elements, or keep the data in a `list`, which lives on a data stack that holds gigabytes:

```lymra
function main()
    variable array[integer64, 100000] samples = array(0)
    samples[0] = 1
    print("{samples[0]}")
```

```lymra
function main()
    variable list[integer64] samples = list()
    for _ in range(0, 1000000)
        push(variable samples, 0)
    samples[0] = 1
    print("{samples[0]}")
```
