# L0103: name does not follow the naming style

A declared name is not in the style Lymra requires for that kind of thing.

| Kind of name | Style | Example |
|---|---|---|
| values, functions, parameters, fields, modules | `snake_case` | `frog_count` |
| types, choices, variants | `PascalCase` | `FrogPond` |

A binding you never read can be named `_`.

## Example

```lymra
type frog_pond
    unsigned32 FrogCount

function CountFrogs(frog_pond pond) returns unsigned32
    return pond.FrogCount
```

## Why

When every project spells names the same way, you can tell a type from a value at a glance and move between codebases without relearning a style. Making it a rule also ends the argument about which style to use.

Only declarations are checked. A use of a badly named thing is not reported again.

## Fix

Rename the declaration as the message says, then rename every use.

```lymra
type FrogPond
    unsigned32 frog_count

function count_frogs(FrogPond pond) returns unsigned32
    return pond.frog_count
```
