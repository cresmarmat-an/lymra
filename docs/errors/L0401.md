# L0401: `match` does not handle each variant once

A `match` has a `case` for every variant of its choice, and only one. This one leaves a variant out, handles one twice, or names something that is not a variant of the choice.

## Example

```lymra
choice Light
    Red
    Amber(integer64 seconds)
    Green

function wait(Light light) returns integer64
    match light
        case Red
            return 60
        case Amber(seconds)
            return seconds

function main()
    print("{wait(Green)}")
```

## Why

A choice is exactly one of its variants, and a `match` says what happens for each. When a declaration gains a variant, every `match` that does not handle it stops compiling, so the new variant cannot be forgotten anywhere. A case for every other variant, like `_` in Rust or `default` in C, would take the new variant in without a word, so Lymra has none. A second `case` for one variant could never run.

## Fix

Add a `case` for each variant that is missing.

```lymra
choice Light
    Red
    Amber(integer64 seconds)
    Green

function wait(Light light) returns integer64
    match light
        case Red
            return 60
        case Amber(seconds)
            return seconds
        case Green
            return 0

function main()
    print("{wait(Green)}")
```
