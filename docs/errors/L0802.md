# L0802: type a function cannot fail with

A function fails with a value that does not grow and holds no view or handle: a number, a `boolean`, text, or an array, a declared type or a choice made of them.

## Example

```lymra
function check(integer64 value) fails list[integer64]
    if value < 0
        fail list()

function main()
    match check(5)
        case Success
            print("fine")
        case Failure
            print("negative")
```

## Why

A failure travels up through the calls that pass it on with `try`, and each of them frees what it built on the way. A list keeps its elements on a data stack of the function that made it, so it would be freed while the failure still holds it. A view or a handle names data that something else keeps, which the failure could outlive in the same way. A value of fixed size, or one that holds text, is copied to each caller as a returned value is (Section 4.5), so it is always safe to pass on.

## Fix

Fail with a choice that says what went wrong, and give it the values that explain it:

```lymra
choice CheckError
    Negative(integer64 value)

function check(integer64 value) fails CheckError
    if value < 0
        fail Negative(value = value)

function main()
    match check(5)
        case Success
            print("fine")
        case Failure(error)
            match error
                case Negative(value)
                    print("{value} is negative")
```
