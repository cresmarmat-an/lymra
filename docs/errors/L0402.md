# L0402: mismatched types

A value has a different type than the place it is used: a binding's declared type, a parameter, a return type, the two sides of an operator, a condition, or the argument of `print`.

## Example

```lymra
function main()
    constant integer64 count = 3
    constant unsigned8 small = count
    print("{small}")
```

## Why

Lymra never converts a value to another type by itself. An automatic conversion can lose information without a trace: in C, copying a large `integer64` into an `unsigned8` silently keeps only its lowest 8 bits.

The same rule covers conditions. An `if` needs a `boolean`, so `if count` is an error; write the comparison you mean, such as `if count != 0`. And `print` takes text: interpolate other values into it, as in `print("{count}")`.

An integer literal is the one exception. It has no type of its own and takes the type its place asks for, as long as the value fits.

To use an integer as another integer type, convert it explicitly with a `to_` function such as `to_unsigned8`. A conversion that could lose the value is checked when the program runs.

## Fix

Give both places the same type:

```lymra
function main()
    constant unsigned8 count = 3
    constant unsigned8 small = count
    print("{small}")
```

Or convert the value, which stops the program if it does not fit:

```lymra
function main()
    constant integer64 count = 3
    constant unsigned8 small = to_unsigned8(count)
    print("{small}")
```
