# L0416: shift count outside the bits of its value

A `shift_left` or `shift_right` has a count, known while compiling, that is below 0 or not below the number of bits of the value it shifts.

## Example

```lymra
function main()
    variable unsigned64 flags = 5
    flags = flags + 1
    print("{shift_left(flags, 64)}")
```

## Why

A value of 64 bits can be shifted by 0 to 63 bits. A shift by 64 or more has no meaning the language can give it: in C it is undefined behavior, and the processors that run C disagree on what it does, from leaving the value alone to clearing it. When the compiler can see that a count is outside the bits of its value, the line can never succeed, so it is rejected before the program runs. A count known only at run time is checked when the program runs, and one outside the bits stops the program with a runtime error.

## Fix

Shift by a count from 0 to one less than the bits of the value. To get a value with every bit shifted out, write that value, 0, instead.

```lymra
function main()
    variable unsigned64 flags = 5
    flags = flags + 1
    print("{shift_left(flags, 63)}")
```
