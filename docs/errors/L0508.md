# L0508: binding changed and used in one expression

An expression passes a binding with `variable`, so the call may change it, and the same expression also uses that binding somewhere else: it reads it, or passes it with `variable` a second time.

## Example

```lymra
function take_one(variable integer64 count) returns integer64
    count = count - 1
    return 1

function main()
    variable integer64 apples = 5
    constant total = apples + take_one(variable apples)
    print("{total} {apples}")
```

## Why

`apples + take_one(variable apples)` reads `apples` and changes it. The parts of an expression run from left to right, so the read would come first and `total` would be 6, while `take_one(variable apples) + apples` would give 5. Nothing on the line shows that one part changes what another reads, so swapping two operands, which looks harmless, would change the result. Passing one binding with `variable` twice, as in `swap(variable first, variable first)`, has the same problem: the result depends on which change lands last. Lymra rejects the expression instead of making you remember the order.

The rule also keeps code fast: since no part of an expression can change what another part reads, the compiler only has to keep the order of the parts that print or can stop the program, and is free to arrange the rest.

The rule applies to one expression at a time: a value, an argument list, the condition of an `if` or of each `else if`. Statements run one after another, so splitting the expression into statements always makes the order plain.

## Fix

Call the function in a statement of its own and save its result in a `constant`. The statements after the call see the changed binding. If you need the value from before the call, save it first.

```lymra
function take_one(variable integer64 count) returns integer64
    count = count - 1
    return 1

function main()
    variable integer64 apples = 5
    constant before = apples
    constant taken = take_one(variable apples)
    constant total = before + taken
    print("{total} {apples}")
```
