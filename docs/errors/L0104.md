# L0104: index not proven in range

A file that starts with `#!prove bounds` asks the compiler to prove that every index stays inside its array. This index could not be proven: the error says which values the compiler knows the index can have at that point, which may be none at all for a parameter.

## Example

```lymra
#!prove bounds

function at(array[integer64, 4] values, integer64 position) returns integer64
    return values[position]

function main()
    constant array[integer64, 4] values = array(7)
    print("{at(values, 2)}")
```

## Why

Every index is checked when the program runs, and the compiler removes the checks it can prove unnecessary. `#!prove bounds` turns that into a promise: the file compiles only if no check is left, so a hot loop gets code without checks and keeps its safety. Languages that let you switch checks off instead trust the programmer, and a wrong guess reads or writes memory it should not.

The compiler learns about a value from the bounds of `for` loops over `range`, the conditions of `if`, `while` and `assert`, and known values. A parameter can hold any value of its type, until a condition says otherwise.

## Fix

Check the index once, where the compiler can see it: with an `if`, or an `assert` before the loop. An `assert` costs one check, instead of one for every index in the loop after it, and the program stops at the `assert` if it ever fails.

```lymra
#!prove bounds

function at(array[integer64, 4] values, integer64 position) returns integer64
    assert position >= 0 and position < length(values)
    return values[position]

function main()
    constant array[integer64, 4] values = array(7)
    print("{at(values, 2)}")
```
